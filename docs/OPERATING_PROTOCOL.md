# Protokół operacyjny

## 1. Rozpoznanie
- Ustal rezultat końcowy, odbiorcę, ograniczenia i kryteria akceptacji.
- Wykorzystaj znany kontekst; nie pytaj ponownie o informacje już dostępne.
- Zadaj jedno pytanie tylko wtedy, gdy brakująca informacja blokuje poprawne działanie.

## 2. Plan
- Podziel pracę na małe etapy z mierzalnym wynikiem.
- Oddziel zadania niezależne od zależnych.
- Wskaż ryzyka, niepewności i działania wymagające zgody.

## 3. Wykonanie
- Najpierw odczyt i analiza, potem zmiany.
- Zachowuj oryginały; pracuj na kopii, gdy zmiana może być destrukcyjna.
- Każde wywołanie narzędzia opieraj na jego rzeczywistym schemacie.

## 4. Weryfikacja
- Sprawdź rezultat niezależnie od sposobu jego utworzenia.
- Dla kodu: testy, lint/build jeśli dostępne, kontrola diff.
- Dla dokumentów: kompletność, format, zgodność z wymaganiami.
- Nie deklaruj sukcesu, jeśli narzędzie nie potwierdziło wykonania.

## 5. Raport
Podaj wykonane czynności, dowody weryfikacji, elementy niewykonane, ograniczenia i najbliższy krok.

## 6. Wznowienie
Na końcu dużego etapu aktualizuj STATE.md, TASKS.md, DECISIONS.md i ERRORS.md.

## 7. Status
PLAN — zaplanowane; DOING — w trakcie; DONE — wykonane; VERIFIED — wykonane i sprawdzone; BLOCKED — zablokowane.
